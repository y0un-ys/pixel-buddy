# Pixel Buddy Chromium 영상 감지 확장

현재 **Chrome / Chromium Manifest V3용**입니다. Firefox의 확장 런타임과
Safari Web Extension 패키징은 지원하지 않으며, 이 폴더를 그대로 설치할 수 있다고
보장하지 않습니다. Edge 등 Chromium 계열의 별도 브라우저는 아직 검증하지 않았습니다.

## 개발자 모드로 설치

1. 이 저장소를 내려받고, 로컬 영상 상태 수신 기능이 포함된 Pixel Buddy를 실행합니다.
2. Chrome 주소창에 `chrome://extensions`를 입력합니다.
3. 오른쪽 위 **개발자 모드**를 켭니다.
4. **압축해제된 확장 프로그램을 로드합니다**를 누릅니다.
5. 저장소 안의 **`tools/browser_extension` 폴더 자체**를 선택합니다.
   저장소 최상위 폴더나 ZIP 파일이 아닙니다.
6. 확장 목록에서 Pixel Buddy 영상 감지에 오류가 없는지 확인합니다.
7. 이미 열려 있던 영상 페이지는 **새로고침**합니다. 기존 문서에는 새 콘텐츠 스크립트가
   자동으로 들어가지 않습니다. 확장을 다시 로드하거나 업데이트한 뒤에도 새로고침합니다.
8. 툴바의 확장 메뉴에서 Pixel Buddy를 열고 **연결 다시 확인**을 누릅니다.
   `Pixel Buddy 연결됨`을 확인한 뒤 영상을 재생/일시정지하여 상태를 확인합니다.

Chrome에 자동 설치하거나 브라우저 설정을 바꾸는 스크립트는 제공하지 않습니다.
삭제는 `chrome://extensions`에서 **삭제**를 누르면 됩니다.

## 무엇을 감지하나요?

- 모든 허용된 웹 페이지와 프레임의 실제 `HTMLVideoElement`를 관찰합니다.
  동적으로 추가/제거된 영상, 여러 탭, iframe의 상태를 합칩니다.
- `!paused && !ended && readyState >= 2 && videoWidth > 0`인 영상이 하나라도
  있으면 재생 중입니다. 음소거 영상도 포함하며, 오디오 요소는 제외합니다.
- `play`, `playing`, `pause`, `ended`, `emptied` 등 실제 영상 이벤트와 2초
  heartbeat로 갱신합니다. 프레임 보고는 마지막 갱신 6초 뒤 만료됩니다.
  재생 상태 변경은 즉시 전송하고, 동일 상태는 수신 heartbeat 기준 최대 2초에 한 번 전송합니다.
- 탭을 닫거나 새 페이지로 이동하면 해당 탭의 보고를 제거합니다. 개별 iframe이
  사라지면 최대 6초 뒤 다음 메시지/상태 조회에서 만료됩니다.
- MV3 서비스 워커가 중지되면 메모리 상태도 사라집니다. 다음 콘텐츠 heartbeat로
  상태를 다시 구성합니다. 워커를 계속 살려 두거나 기록을 저장하지 않습니다.
  모든 메시지가 끊기면 데스크톱 수신기의 만료 처리로 상태가 해제되어야 합니다.
- 브라우저가 백그라운드/절전 탭의 타이머를 제한하면 재생 중에도 일시적으로
  상태가 해제될 수 있습니다. 앱 종료나 수신기 오류가 나면 팝업에서 연결을 다시 확인하세요.

이는 **창 제목에 YouTube 같은 단어가 있는지 보는 추정과 다릅니다**.
영상 페이지를 열기만 하거나 제목만 일치한다고 재생으로 보고하지 않습니다.
데스크톱 앱의 제목 기반 fallback이 따로 있다면, 그 경로는 이 확장의 실제 재생 보고와
구분해야 합니다.

Chrome 내부 페이지, Chrome 웹 스토어, 브라우저 자체 PDF/미디어 뷰어,
폐쇄형 shadow DOM 안의 영상, 접근이 차단된 프레임/페이지 등에는 적용되지 않을 수 있습니다.
기본적으로 시크릿 모드는 비활성입니다. `file://` 페이지에는 Chrome 확장 상세 화면의
별도 파일 URL 허용 설정이 필요합니다. 화면에 보이는 탭 또는 소리가 나는 영상만
추려 내지는 않습니다. **어느 허용된 탭에서든 실제 재생 중인 영상**을 감지합니다.

## 권한과 개인정보

- 콘텐츠 스크립트의 `<all_urls>` 사이트 접근: 영상 요소의 재생 상태를 모든 사이트와
  iframe에서 감지하는 데 필요합니다. Chrome이 사이트 데이터 접근 경고를 표시할 수 있습니다.
- `http://127.0.0.1/*` 호스트 권한: 이 컴퓨터의 Pixel Buddy 수신기에만 요청합니다.
  Chrome 호스트 권한 패턴은 포트를 제한할 수 없으므로 manifest에는 포트를 쓰지 않지만,
  실제 코드는 **`http://127.0.0.1:38673`만** 사용합니다.
- `tabs`, `history`, `storage` 권한을 요청하지 않습니다. 권한 없이 제공되는 탭
  닫힘/로딩 이벤트에서 숫자 ID만 사용합니다. URL, 제목, 페이지 내용, 키 입력,
  쿠키는 수집/저장/전송하지 않습니다. 외부 서버, 분석 도구, CDN도 없습니다.
- 콘텐츠 메시지는 `{type: "media-state", playing: boolean}`입니다.
  로컬 POST의 JSON은 정확히 다음 두 필드뿐입니다:

  ```json
  {"browser":"chromium","playing":true}
  ```

- `POST http://127.0.0.1:38673/media-state`에 `application/json`으로 보냅니다.
  `GET /health`의 `{"connected":true}` 응답으로 팝업 연결 상태를 확인합니다.
  로컬 수신기는 올바른 Host와 `chrome-extension://` Origin만 허용해야 합니다.
  이 확장은 인증 토큰이나 장기 식별자를 저장하지 않습니다.

## 개발 및 확인

Node.js 20 이상에서 저장소 루트 기준:

```sh
node --test tools/browser_extension/tests/*.test.mjs
```

외부 패키지는 필요 없습니다. 테스트는 가상 시계와 직접 이벤트 신호를 사용하며
sleep이나 실제 시간 경과에 의존하지 않습니다.

실제 브라우저 QA는 위 설치 절차 이후 수행합니다:

1. 연결 확인, 영상 재생, 일시정지, 재생 종료 상태를 확인합니다.
2. 여러 탭/iframe 중 하나만 재생해도 재생 중인지 확인합니다.
3. 재생 탭 닫기/다른 페이지로 이동 후 상태가 해제되는지 확인합니다.
4. `chrome://extensions`에서 서비스 워커를 중지한 뒤 다음 콘텐츠 heartbeat로
   상태가 복구되는지 확인합니다. 강제로 확장을 다시 로드했다면 페이지도 새로고침합니다.
5. Pixel Buddy를 종료하면 팝업에 연결 안 됨이 표시되는지 확인합니다.

Node 테스트는 네이티브 Chrome 설치, 실제 사이트별 동영상 엔진, 수신기와의 실연결을
대신하지 않습니다.
